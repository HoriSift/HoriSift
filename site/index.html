THE WORKFLOW

Evidence first. Guesswork last.

HoriSift examines source files without running your application. Its findings are starting points for engineers, not automated rewrites.

01 / DETECT
⌁

Trace supported usage

Locate recognized Horizon SDK and HTTP patterns, including source paths and positions.

02 / CLASSIFY
▤

Map investigation work

Review 25 versioned advisory rules distinguishing direct, conditional and indexing-dependent cases.

03 / PRESERVE
◇

Keep the unknowns

Dynamic URLs and incomplete coverage stay visible. A clean report never proves that a repository is Horizon-free.

START WITH THE SOURCE

Your code stays on your machine.

HoriSift is not available as a published npm package. Clone the repository and run the development CLI with Node.js 22.12+ or 24.

Read the complete CLI guide ↗
terminal · local checkout
# Node 22.12+ or 24; no target app installed
$ git clone https://github.com/HoriSift/HoriSift.git
$ cd HoriSift
$ npm ci --ignore-scripts
$ npm run cli -- scan ./my-stellar-app --format json

# Reproduce a pinned public-source example
$ npm run example -- axelar-faucet --format json --allow-incomplete

IMPORTANT LIMITATIONS

A report is a question list, not a green light.

HoriSift can miss historical SDK forms, custom hosts, wrappers and cross-file behavior. A real public sample using StellarSdk.Server was missed. Even a complete scan with zero findings is not proof of a Horizon-free application or an approved migration.

Stellar RPC is not a drop-in Horizon replacement; data shapes and historical indexing can require application changes. Read the official Stellar migration guide and the full HoriSift limitations.
